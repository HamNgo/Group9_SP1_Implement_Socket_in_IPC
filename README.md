## Project Overview
Multi-threaded Local Task Offloading & Dual-mode Messaging Daemon via UNIX Domain Sockets (AF_UNIX).

Current stage: **single-client task offloading**. A client reads an input file and sends it to
a server daemon over a UNIX domain socket. The server verifies and processes the data, appends
a timestamped result to `output.txt`, and sends the result back to the client.

## Project Structure
```
Makefile
include/
  protocol.h        wire format, socket path, constants
  utils.h           processing / output-file API
src/
  server.c          daemon: accept loop, one thread per client, signals, graceful shutdown
  client.c          reads the input file, sends it, prints the server's reply
  utils.c           text analysis, transforms, checksum, timestamped output writing
scripts/
  demo_single.sh    narrated single-client demo
samples/
  input.txt         sample input for the demo
```
`bin/` and `obj/` are generated by `make`.

## Build
```bash
make            # builds bin/server and bin/client
make clean      # removes bin/ and obj/
```
Requires `gcc` and `make` on Linux.

## Run

**1. Start the server**
```bash
./bin/server -o output.txt     # background daemon (default)
./bin/server -f -o output.txt  # foreground, logs to the terminal (Ctrl+C to stop)
```
`-o` sets the output file (default `output.txt` in the current directory).

**2. Send a file with the client**
```bash
./bin/client samples/input.txt              # default mode: stats
./bin/client -m stats   samples/input.txt   # lines, words, longest word, most frequent word
./bin/client -m upper   samples/input.txt   # stats + convert to UPPERCASE
./bin/client -m reverse samples/input.txt   # stats + reverse the order of lines
./bin/client --ping                         # health check
```

**3. Check the result**
```bash
cat output.txt
```
Each entry has a timestamp, client PID, filename, mode, size, checksum, result,
processing time and the processed content.

**4. Stop the server**
```bash
kill -TERM $(cat /tmp/ipc_group9_server.pid)   # daemon mode
# or press Ctrl+C in foreground mode
```
The server stops accepting connections, waits up to 30 s for running handlers, writes
`[SYSTEM] Shutdown gracefully` to the output file, and removes the socket and PID file.

## Demo
```bash
./scripts/demo_single.sh        # pauses at each step (press Enter)
./scripts/demo_single.sh -n     # runs straight through
make demo                       # same demo via make
```
The demo covers: daemon start (PPID 1, no terminal), ping, the three processing modes,
`output.txt`, error handling, the syslog lines, and graceful shutdown with `SIGTERM`.

## Error-handling test flags (client)
```bash
./bin/client --bad-checksum samples/input.txt   # server rejects corrupted data (ERR_CHECKSUM)
./bin/client --bad-magic    samples/input.txt   # server rejects a foreign protocol (ERR_PROTOCOL)
```

## Server log
A daemon has no terminal, so it logs through syslog:
```bash
journalctl -t ipc_server -n 20 --no-pager
# or: grep ipc_server /var/log/syslog | tail -20
```

## Troubleshooting
| Symptom | Fix |
|---|---|
| `Cannot connect to /tmp/ipc_group9_stream.sock` | The server is not running. Start it first. |
| `Da co server khac dang chay` | A server is already running. Stop it with the `kill` command above. |
| Stale socket after a crash | `rm /tmp/ipc_group9_stream.sock /tmp/ipc_group9_server.pid` |
| `output.txt` not where expected | In daemon mode the path is resolved from the directory where the server was started; use `-o /full/path`. |
| Link errors about `write_system_log` / `process_and_store` | `src/utils.c` is missing from the repo. |
